# 报告生成工作流

## 并行子代理生成模式

由于报告需要达到100页以上的细致程度，单个子代理生成会超时或质量不足。采用3个子代理并行生成：

### 分段策略

| 部分 | 内容 | 预计大小 | 预计页数 |
|------|------|----------|----------|
| 第一部分 | 第一阶段：问题分析（课题信息→聚焦关键问题） | 65-90 KB | ~40页 |
| 第二部分 | 第二阶段：方案产出（11题路由→方案说明书） | 99-110 KB | ~40页 |
| 第三部分 | 第三阶段：方案落地（实施路线图→结论+附录） | 55-115 KB | ~25页 |

### 生成流程

1. **同时启动3个子代理**：使用 `delegate_task` 的 batch 模式
2. **等待全部完成**：每个子代理约5-20分钟
3. **合并报告**：`cat part1.md part2.md part3.md > 完整版.md`
4. **统计页数**：`wc -l` 除以30得到近似页数

### 合并命令

```bash
cat "/c/Users/jianw/Documents/TRIZ_报告_XXX_第一部分.md" \
    "/c/Users/jianw/Documents/TRIZ_报告_XXX_第二部分.md" \
    "/c/Users/jianw/Documents/TRIZ_报告_XXX_第三部分.md" \
    > "/c/Users/jianw/Documents/TRIZ_报告_XXX_完整版.md"
```

### 质量验证

合并后检查：
- 文件大小 > 200 KB（对应约80+页）
- 总行数 > 2500 行
- 无重复章节标题
- 附录包含流程检查清单和质量自评

## 报告质量自评（10维度）

报告末尾必须包含自评，10个维度各10分，满分100分：

1. 流程完整度
2. 详细度
3. 数据支撑
4. 表格规范
5. 专利分析深度
6. 方案可行性
7. 次级问题分析
8. 实施示例
9. 创新性
10. 可读性

详见 AGENTS.md 中的"报告质量自评"章节。
