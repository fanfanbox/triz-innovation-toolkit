# 单代理顺序报告生成模式

## 概述

当不使用并行子代理时，采用**顺序文件写入 + 合并**模式生成大型报告。每个部分写入临时文件，最后合并为完整报告。

## 适用场景

- 单代理生成（无子代理能力）
- 报告各部分有数据依赖（如专利数据需传递到后续部分）
- 会话上下文充足（不需要跨子代理传递）

## 执行流程

```
1. 确定报告结构（章节划分）
2. 对每个章节：
   a. 生成内容
   b. 写入临时文件（命名：{报告名}_第N部分.md）
3. 合并所有临时文件：
   cat 第1部分.md 第2部分.md ... > 完整版.md
4. 验证：wc -c（字节数）+ wc -l（行数）
5. 清理临时文件
```

## 命名规范

```
临时文件：{报告名}_{序号}.md
最终文件：{报告名}_完整版.md

示例：
TRIZ_报告_多级相变热管理_第二部分_01.md  ← 临时
TRIZ_报告_多级相变热管理_第二部分_02.md  ← 临时
TRIZ_报告_多级相变热管理_完整版_第二部分.md  ← 最终
```

## 合并命令

```bash
# 合并
cat part_01.md part_02.md part_03.md > final.md

# 验证
wc -c final.md  # 字节数
wc -l final.md  # 行数
grep -c "^|" final.md  # 表格行数
grep -c "^## " final.md  # 一级章节数

# 清理
rm -f part_*.md
```

## 质量参考（第二部分：方案产出）

| 指标 | 达标值 | 说明 |
|------|--------|------|
| 文件大小 | 80-120 KB | ~40页内容 |
| 行数 | 1,500-2,500 行 | 含大量表格 |
| 一级章节 | 10+ 个 | 11题路由+2.1~2.9+总结 |
| 表格行数 | 500+ 行 | 每个分析项都有详细表格 |
| 专利数量 | 20+ 件 | 深度分析 |

## 与并行子代理模式的对比

| 方面 | 顺序模式 | 并行子代理模式 |
|------|----------|--------------|
| 速度 | 较慢（串行） | 快（3段并行） |
| 上下文 | 完整（共享上下文） | 分离（需传递） |
| 数据一致性 | 高（同一上下文） | 需要验证边界 |
| 适用复杂度 | 中小报告 | 大型100页+报告 |
| 实现难度 | 低 | 高（需子代理支持） |
