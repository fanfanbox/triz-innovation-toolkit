# 大型报告并行生成模式（100页+）

## 概述

生成100页以上的详细TRIZ分析报告时，采用3个并行子代理分段生成，然后合并为完整报告。
经6个项目验证：主驱电机、电涡流传感器、电磁优化、槽内油冷、母线电容、P1/P3功率模块。

## 为什么分段

- 单次生成100+页会超时或质量下降（上下文溢出）
- 并行生成节省时间（3段同时进行，约10-15分钟完成）
- 每段可独立验证质量

## 分段结构

| 部分 | 内容 | 预计大小 | 预计耗时 |
|------|------|----------|----------|
| 第一部分 | 第一阶段：问题分析（课题收集→课题梳理→功能分析→裁剪→因果链→聚焦关键问题） | 60-90 KB | 5-8 min |
| 第二部分 | 第二阶段：方案产出（11题路由→专利挖掘→矛盾分析→物场分析→功能导向搜索→方案说明书） | 90-110 KB | 10-20 min |
| 第三部分 | 第三阶段：方案落地（实施路线图→原理样件设计→结论→质量自评） | 50-115 KB | 5-10 min |

## 执行步骤

1. **准备课题信息**：从用户输入或图片识别，提取完整的课题信息表
2. **并行启动3个子代理**（delegate_task，role=leaf）：
   - 每个子代理的 prompt 包含：课题信息 + 对应阶段结构要求 + 详细度要求 + 输出路径
3. **轮询等待**：用 `sleep && ls` 循环检查文件是否生成
4. **合并报告**：
   ```bash
   cat 第一部分.md 第二部分.md 第三部分.md > 完整版.md
   ```
5. **验证**：检查文件大小和行数（预期 240-280 KB, 2700-3500 行）

## 子代理 Prompt 结构

每个子代理 prompt 必须包含：

```
1. 上下文说明（"这是一个XX工程师的TRIZ创新分析报告"）
2. 课题完整信息：
   - 技术难题/课题名称
   - 技术领域
   - 技术背景
   - 技术问题（编号列表）
   - 课题目标（量化指标）
   - 产品/技术系统名称
   - 系统组件
   - 外部组件
3. 对应阶段的详细结构要求（每个章节的页数目标）
4. 详细度要求：
   - 每个分析项目都必须有详细表格
   - 表格内容必须具体、有数据支撑
   - 禁止使用简单列表替代详细表格
   - 禁止省略分析过程只给结论
   - 禁止使用泛化描述替代具体数据
   - 禁止跳过次级问题分析
5. 输出文件路径
```

## Pitfalls

### ⚠️ 第二部分耗时最长

第二部分（方案产出）通常耗时最长（10-20分钟），因为包含专利分析和ARIZ-85C深度分析。
第三部分最快（5-10分钟）。如果某部分超时（>20分钟），检查文件是否已生成再决定是否重新调度。

### ⚠️ 文件编码（Windows）

Windows 环境下，子代理生成的文件可能包含 BOM 或 \r\n 换行符。
合并后用 `wc -l` 验证行数，用 `file` 命令检查编码。

### ⚠️ 内容重复

三个子代理独立工作，可能在边界处有重复内容（如"关键问题汇总"出现在第一部分末尾和第二部分开头）。
合并后人工检查边界衔接。

### ⚠️ 轮询间隔

子代理通常需要 5-20 分钟完成。建议轮询间隔：
- 前 5 分钟：每 60 秒检查一次
- 5-15 分钟：每 120 秒检查一次
- 15 分钟后：每 180 秒检查一次

### ⚠️ 子代理失败处理

如果某个子代理失败或超时：
1. 检查部分生成的文件是否有效
2. 如果文件完整，直接使用
3. 如果文件缺失或不完整，重新调度该子代理
