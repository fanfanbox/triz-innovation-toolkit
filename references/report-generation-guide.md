# 报告生成指南 — 100页以上详细报告

## 生成策略

由于单次生成无法达到100页以上，必须分段生成后合并。

### 三段式并行生成

使用3个子代理并行生成报告的三个部分：

```
第一部分（第一阶段：问题分析）     → ~40页  → TRIZ_报告_<课题>_第一部分.md
第二部分（第二阶段：方案产出）     → ~40页  → TRIZ_报告_<课题>_第二部分.md
第三部分（第三阶段：方案落地）     → ~25页  → TRIZ_报告_<课题>_第三部分.md
                                    ↓ 合并
                              TRIZ_报告_<课题>_完整版.md (~105页)
```

### 子代理调用模板

每个子代理需要提供：
1. **课题信息** — 完整的技术背景、问题描述、目标、组件清单
2. **报告结构要求** — 各章节页数分配
3. **详细度要求** — 禁止简单列表、必须有详细表格等
4. **输出路径** — 明确的文件保存位置

### 合并命令

```bash
cat "第一部分.md" "第二部分.md" "第三部分.md" > "完整版.md"
```

## Word 转换

使用 pandoc 转换，添加技术报告元数据：

```bash
pandoc "完整版.md" -o "完整版.docx" \
  --from markdown \
  --to docx \
  --metadata title="TRIZ 系统化创新分析报告" \
  --metadata date="$(date '+%Y年%m月%d日')" \
  --metadata subject="TRIZ Innovation Analysis" \
  --metadata keywords="TRIZ, 创新, 电机设计, 专利分析"
```

### 批量转换

```bash
for file in TRIZ_*_完整版.md; do
  name="${file%.md}"
  pandoc "$file" -o "${name}.docx" --from markdown --to docx \
    --metadata title="TRIZ 系统化创新分析报告" \
    --metadata date="$(date '+%Y年%m月%d日')"
done
```

## 质量自评（10维度）

| 维度 | 评估标准 | 评分 (1-10) |
|------|----------|-------------|
| 1. 流程完整度 | 三阶段流程是否完整覆盖 | |
| 2. 详细度 | 每个步骤是否详细展开 | |
| 3. 数据支撑 | 表格内容是否有具体数据 | |
| 4. 表格规范 | 表格是否规范、完整 | |
| 5. 专利分析深度 | 专利≥20件，子方向≥4个 | |
| 6. 方案可行性 | 方案是否具体可行 | |
| 7. 次级问题分析 | 是否分析了次级问题 | |
| 8. 实施示例 | 是否有具体实施示例 | |
| 9. 创新性 | 方案是否有创新性 | |
| 10. 可读性 | 报告是否易于理解 | |

评分标准：优秀(9-10)、良好(7-8)、一般(5-6)、较差(3-4)、很差(1-2)
