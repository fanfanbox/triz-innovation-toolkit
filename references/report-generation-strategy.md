# 报告生成策略

## 背景

单次生成100页以上的报告会导致上下文溢出或质量下降。采用**3段并行生成**策略可确保每个部分都有足够的上下文空间。

## 三段并行策略

### 分段规则

| 部分 | 内容 | 预计页数 | 文件名模式 |
|------|------|----------|------------|
| 第一部分 | 第一阶段：问题分析（1.1-1.6） | ~40页 | `TRIZ_报告_<课题>_第一部分.md` |
| 第二部分 | 第二阶段：方案产出（路由诊断 + 2.1-2.9） | ~40页 | `TRIZ_报告_<课题>_第二部分.md` |
| 第三部分 | 第三阶段：方案落地（3.1-3.3 + 附录） | ~25页 | `TRIZ_报告_<课题>_第三部分.md` |

### 并行执行流程

```
1. 启动 3 个 delegate_task（role=leaf），并行执行
2. 每个子代理独立生成对应部分
3. 等待所有子代理完成
4. 合并：cat 第一部分 第二部分 第三部分 > 完整版.md
5. 统计：wc -l + ls -lh 确认页数
```

### 合并命令

```bash
cat "TRIZ_报告_<课题>_第一部分.md" \
    "TRIZ_报告_<课题>_第二部分.md" \
    "TRIZ_报告_<课题>_第三部分.md" \
    > "TRIZ_报告_<课题>_完整版.md"
```

### 预计产出

| 指标 | 范围 |
|------|------|
| 文件大小 | 240-281 KB |
| 总行数 | 2,700-3,500 行 |
| 预计页数 | 90-120 页 |

## 每个子代理的上下文要求

每个子代理必须包含：
1. **完整的课题信息**（技术难题、技术领域、技术背景、技术问题、课题目标、系统组件、外部组件）
2. **详细的报告结构要求**（每个章节的页数和内容要求）
3. **详细度要求**（禁止事项清单）

## Pitfalls

### ⚠️ 子代理可能超时

部分子代理可能需要 8-10 分钟完成。如果某个子代理未完成，需要等待或重新启动。

### ⚠️ 合并后需要验证

合并后必须检查：
- 文件大小是否合理（>200KB）
- 总行数是否足够（>2500行）
- 三个部分是否都包含在内

### ⚠️ 课题信息必须完整

如果课题信息不完整（如缺少技术问题描述、课题目标），生成的报告会过于泛化。必须在课题收集阶段（1.1）完成3轮追问。
