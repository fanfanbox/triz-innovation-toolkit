# 方案辩论系统 (Solution Debate System)

TRIZ 报告生成后的多子代理对抗性辩论系统，通过正反两派辩论 + 落地分析，输出可执行性最强的 Top 3 方案。

## 架构概览

```
Phase 1-3: TRIZ报告生成（3子代理并行）
    │
    ▼ 提取方案矩阵（8-12个候选方案）
    │
    ┌─── Round 1: 辩论（并行）──────────┐
    │  🟢 正方  ──→ 可行性评分+论据     │
    │  🔴 反方  ──→ 风险评分+反驳       │
    └──────────────┬───────────────────┘
                   ▼ 收敛检查
    ┌─── Round 2: 交叉反驳（条件触发）──┐  ← 如未收敛
    │  🟢 正方再论证  ──→ 更新评分      │
    │  🔴 反方再反驳  ──→ 更新评分      │
    └──────────────┬───────────────────┘
                   ▼ 收敛检查
    ┌─── Round 3: 最终交锋（最多3轮）──┐  ← 如仍未收敛
    │  最终论据交换 → 强制收敛          │
    └──────────────┬───────────────────┘
                   ▼
    ┌─── 裁决+落地分析（并行）─────────┐
    │  🟡 裁判          ──→ Top3 筛选   │
    │  🟠 落地分析专家   ──→ 8维度分析   │
    └──────────────┬───────────────────┘
                   ▼
    合并 → 辩论+落地报告 → 追加到完整报告
```

## 收敛判定机制（方案三+方案四混合）

### 收敛信号

| 信号 | 检测方法 | 权重 |
|------|----------|------|
| **排名稳定性** | Top 3 排名连续 N 轮不变 | 50% |
| **评分变化量** | 综合得分变化 ΔS < ε | 30% |
| **论据饱和度** | 无新论据出现（仅重复强化） | 20% |

### 收敛状态定义

```python
def evaluate_convergence(M_prev, M_curr, epsilon=0.3, k=3):
    # 信号1: 排名稳定性
    scores_prev = sorted(M_prev.items(), key=lambda x: x[1]["net"], reverse=True)
    scores_curr = sorted(M_curr.items(), key=lambda x: x[1]["net"], reverse=True)
    rank_prev = [s[0] for s in scores_prev[:k]]
    rank_curr = [s[0] for s in scores_curr[:k]]
    rank_stable = (rank_prev == rank_curr)

    # 信号2: 评分变化量
    max_delta = max(abs(M_curr[s]["net"] - M_prev[s]["net"]) for s in M_curr)

    # 信号3: Top K 与后续方案的分差
    gap = scores_curr[k-1][1]["net"] - scores_curr[k][1]["net"] if len(scores_curr) > k else 999

    # 综合判定
    if rank_stable and max_delta < epsilon and gap > 0.5:
        return "CONVERGED", 0.9
    elif rank_stable and max_delta < epsilon * 1.5:
        return "NEAR_CONVERGED", 0.75
    elif rank_stable:
        return "WEAK_CONVERGENCE", 0.6
    else:
        return "DIVERGING", 0.5
```

### 收敛流程

```
Round 1 (必须): 正方+反方 → M1 → R1
  ├── Top3与第4名差距 > 1.0 → CONVERGED
  └── 否则 → Round 2

Round 2 (条件): 交叉反驳 → M2 → R2
  ├── R1[:3]==R2[:3] 且 ΔS<0.3 → CONVERGED
  ├── R1[:3]==R2[:3] 但 ΔS≥0.3 → NEAR_CONVERGED
  └── 排名变化 → Round 3

Round 3 (最多3轮): 最终交锋 → 强制收敛，置信度=LOW(0.6)
```

### 置信度映射

| 收敛方式 | 置信度 | 说明 |
|----------|--------|------|
| 1轮收敛 | HIGH (0.9) | 方案差距明显 |
| 2轮收敛 | MEDIUM-HIGH (0.8) | 排名稳定 |
| 2轮近似收敛 | MEDIUM (0.75) | 评分接近收敛 |
| 3轮强制 | LOW (0.6) | 高度竞争 |

```
【课题信息】{课题名称/描述/技术领域/核心矛盾}
【候选方案矩阵】{方案编号/名称/原理/预期效果}

【评分维度】(1-10分，必须引用具体数据/专利号/行业案例)

- 资源可获得性 × 0.15

- 成本效益比 × 0.20

{如有反方反驳，要求针对性回应}

【输出表格】
```


### 🟡 裁判 (Judge)

```
你是一位资深技术决策顾问（裁判），综合正反方辩论结果，筛选 Top 3 方案。

【正方评分矩阵】{正方输出}
【反方评分矩阵】{反方输出}

【评分公式】综合得分 = 正方综合评分 × 0.6 - 反方综合风险 × 0.4

{如有历史轮次数据，附上前几轮评分矩阵和排名}

【输出】
1. 收敛判定（状态/置信度/理由）
2. 综合评分矩阵（方案/正方评分/反方风险/综合得分/排名/排名变化）
3. Top 3 裁决（每个方案：论据对比/裁决理由/CSF/最大风险）
4. 淘汰方案及原因
```

### 🟠 落地分析专家 (Implementation Strategist)

```
你是资深市场战略顾问。裁判已筛选出 Top 3 方案，为每个方案输出完整落地分析。

【Top 3 方案信息】{裁判输出}
【课题背景】{课题名称/描述/技术领域}

对每个Top方案完成8维度分析（必须有详细表格和量化数据）：

维度1：市场规模与机会（TAM/SAM/SOM/增长率/客户画像/付费意愿）
维度2：竞争格局（直接/间接竞争对手/优劣势矩阵/红海蓝海判断）
维度3：护城河策略（技术/产品/生态/时间护城河+专利布局计划含IPC分类号）
维度4：成本优化（BOM分解/规模效应曲线1K→100K/目标成本vs竞品）
维度5：Go-to-Market（目标客户/渠道/定价/首批客户获取）
维度6：实施路线图（短/中/长期里程碑+Gate Review）
维度7：风险矩阵（技术/市场/财务/政策风险+缓解+应急预案）
维度8：投资回报（总投资/3情景收入/盈亏平衡/IRR/NPV/回收期）

最终决策：Go / No-Go / 条件Go + 理由 + 前置条件
```

## 执行流程

1. **提取方案矩阵**：从报告Part2的2.6或2.9章节提取
2. **Round 1**：并行启动正方+反方子代理
3. **收敛检查**：解析评分，调用收敛判定函数
4. **Round N**：如未收敛，启动交叉反驳（最多3轮）
5. **裁决+落地**：并行启动裁判+落地专家
6. **合并输出**：辩论报告+落地分析 → 第四部分

## 配置参数

```yaml
debate:
  max_rounds: 3
  convergence_epsilon: 0.3
  convergence_gap: 0.5
  scoring_weights: {feasibility: 0.6, risk: 0.4}
```

## Pitfalls

### ⚠️ 评分自洽性
正方倾向高分，反方倾向高风险。裁判必须用公式标准化。

### ⚠️ 收敛阈值
epsilon=0.3 适用多数场景。方案相似时降到0.2，差异大时提到0.5。

### ⚠️ 数据支撑
落地分析必须引用具体数据，缺乏数据时标注"经验估算"。

### ⚠️ 不替代技术验证
辩论筛选"理论最优"，实际落地仍需原型验证。

### ⚠️ Token控制
4角色×3轮=最多12次调用，建议限制输出字数。
